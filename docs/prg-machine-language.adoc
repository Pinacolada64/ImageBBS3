==== `++ copier`

The file "`protocol`" Image uses in Console Local mode, and the copier behind `i.CP` (Copy-All).
It copies between two files your module has already opened: it reads file #3 and writes file #2.
It doesn't close them, except as noted.

[%header]
[%autowidth]
|===
| Function | Purpose | Returns
| `&,16,0` | Copy all of file #3 to file #2, in blocks of up to 254 bytes, until the end of #3. `Good:` counts the blocks. | _n/a_
| `&,16,1` | Count the bytes in file #3 (`Bytes:` counts them), write the count to file #2 as 3 bytes, low byte first, then close #3. | _n/a_
| `&,16,2` | "`Copy some`": read a 3-byte count (low byte first) from file #3, then copy that many more bytes of #3 to #2. A count of 0 copies to the end of #3. | _n/a_
| `&,16,3` | Compare file #3 with file #2, both opened for reading, a block at a time (`Bytes:` counts the bytes compared). | `a%`=0 if they're the same, 1 if not; `b%`=the number of the first byte that differs, or of the first byte past the end of the shorter file
| `&,16,255` | Report the protocol number. Modules check it: `i.UX` refuses transfers when `pr=2` (the copier). | `a%`=2
|===

`&,16,1` and then `&,16,0` into the same file #2 writes a file behind its own length.
`&,16,2` on the result copies that file back out and stops at its end, so a file of several such entries can be unpacked one at a time.

`&,16,0`, `&,16,2` and `&,16,3` read each block into screen memory (`$0400`, rows 0-6), so the bytes being copied or compared show at the top of the screen.
Print below row 6 while they run.

The counters are the digits of row 15 of the protocol screen that `sub.display` draws (`im=5:gosub 443`):

 Good: 00000  Bad: 00000  Bytes: 000000

.Copy one file (condensed from i.CP)
[source]
----
open3,f,3,f$+c$+",r":open2,g,2,g$+c$+",w":&,16:close2:close3
----

[NOTE]
====
Closing a drive's command channel (15) makes the drive close every file it has open.
`im` lines 3, 4, 18 and 19 all close and reopen channel 15, so do them before opening the other file, not after.
Once a file is open, open the next one with `gosub 2` (which only sets `dv%` and `dr$`) and a plain `open`, as `i.test copier` does, or use a second command channel, as `i.CP` does.
====

Test program: `core/tests/i.test copier.lbl`.

===== `&,16,3`: Compare Two Files

`&,16,3` compares two files your module has opened for reading, as file #3 and file #2.

It reads up to 254 bytes of #3 into its buffer, then reads the same number of bytes of #2, checking each one against the buffer as it arrives.
It repeats until it finds a difference, or one of the files ends.
`Bytes:` on the protocol screen counts the bytes compared.

It's much faster than comparing in BASIC with `get#`, which makes the drive switch between the two files for every byte.

_Parameters:_ none.
Open both files for reading first, #3 and #2; it doesn't matter which file is which.
It doesn't close them.

_Returns:_

`a%`: `0` if the files are the same (same length, same bytes); `1` if not.

`b%`: when `a%=1`, the number of the first byte that differs (the first byte is `1`).
If the files are the same up to where the shorter one ends, it's the first byte past that end.
`b%` holds only the low 16 bits of the position, so past byte 32767 it isn't the true position.

.Compare e.copier copy with ++ 2 (condensed from i.test copier)
[source]
----
dr=3:a$="e.copier copy,p,r":gosub 4:if e% then close 2:&:return
dr=5:gosub 2:open 3,dv%,3,dr$+"++ 2,p,r"
&,16,3:close 2:close 3
if a% then:&"They differ at byte {pound}%b.{f6}":return
&"They match.{f6}"
----

NOTE: `&,16,3` is new in this repository (October 2026).
The `++ copier` in the 12/31/2023 release ignores it: `a%` and `b%` are left as they were.

==== `++ menu2`: Graphic Menu

The ML module `++ menu2` draws a framed menu of items, then lets the user move a highlight with the cursor keys and choose an item with kbd:[Return] or the item's hotkey.
`i.IM` (the configuration editor), `i.GF` and `i.UU` (the user editor) use it, and so do `i.DE`, `i.SM` and `i_lo.on` in the 12/31/2023 release.

Every call starts with the same three parameters:

`&,16,_function_,_size_,_menu%(field,item)_`

`function`: 0-3, below.
`function` and `size` are the `&` call's _x_ and _y_ values, so they reach the module in the X and Y registers.

`size`: the number of bytes in one menu item: 2 × (the array's first dimension + 1).
For example, `34` for `dim m%(16,n)`, `42` for `m%(20,n)`, `46` for `m%(22,n)`.
The longer the item, the longer the title it can hold (`size` − 14 characters).

`menu%(field,item)`: the integer array of menu items.
Functions 0 and 1 name the item to fill in; functions 2 and 3 name the first item of the menu.

[%header]
[%autowidth]
|===
| Function | Purpose | Returns
| `&,16,0` | Add one menu item | _n/a_
| `&,16,1` | Add menu items from a struct array | `a%`=records checked, `b%`=items added
| `&,16,2` | Draw the menu, then let the user choose | `a%`=item chosen (0 for the first)
| `&,16,3` | Let the user choose from a menu already drawn | `a%`=item chosen (0 for the first)
|===

===== Menu Items

Each item is one record of the array.
`m%(3,i)` holds the hotkey, so `chr$(m%(3,i) and 255)` is the key of item `i` (as `i.GF` does).

[%header]
[%autowidth]
|===
| Field | Bytes | Contents
| `m%(0,i)` | 0-1 | screen column, row (filled in by `&,16,2`)
| `m%(1,i)`, `m%(2,i)` | 2-5 | the item to move to on kbd:[↑], kbd:[↓], kbd:[→], kbd:[←] (filled in by `&,16,2`)
| `m%(3,i)` | 6-7 | hotkey prefix (0 for none, or e.g. kbd:[/]), hotkey
| `m%(4,i)` | 8-9 | value: 0, or a record number (`&,16,1`)
| `m%(5,i)`-`m%(6,i)` | 10-13 | up to 4 characters printed before the hotkey
| `m%(7,i)`... | 14- | the item's title
|===

===== `&,16,0`: Add Menu Item

`&,16,0,_size_,_menu%(0,item)_,_"hotkey"_,_"prefix"_,_"title"_`

`hotkey`: one key (kbd:[B]), or a prefix and a key (kbd:[/B]) typed one after the other.

`prefix`: up to 4 characters printed before the hotkey, often `""`.

`title`: the text of the menu item.

CAUTION: `hotkey` mustn't be empty: `++ menu2` doesn't check, and the item gets whatever two bytes happen to be where the string would be.

.i.IM: add menu items
[source]
----
&,16,.,34,m%(.,1),"A","","Macros Editor"
&,16,.,34,m%(.,2),"B","","Command Set"
----

.i.GF: add a menu item with a two-key hotkey
[source]
----
3518 if pf>1 then:&,16,0,42,q%(0,n),"/B","Op ","Return to Previous Menu":n=n+1
----

===== `&,16,1`: Add Menu Items from a Struct Array

`&,16,1,_size_,_menu%(0,item)_,_"hotkey"_,_types$_,_recsize_,_flags_,_mask_,_type_,_title_,_titlelen_,_count_,_most_,_value_`

This makes menu items from records of a struct array: for example, the subboards a user may enter.
`flags`, `type` and `title` name those fields of the first record to look at.
Of the next `count` records, each one with any bit of `mask` set in its `flags` field becomes a menu item, up to `most` items.

`hotkey`: the hotkey of the first item added; the next gets the next character, and so on (kbd:[1], kbd:[2], kbd:[3]...).

`types$`: a table of 4-character prefixes. Each item's prefix is the 4 characters starting at position (`type` and 255) × 4.

`recsize`: the number of bytes in one record of the struct array.

`titlelen`: the number of bytes of the `title` field to copy (at most `size` − 14).

`value`: the value stored with the first record checked; each record after that adds 1.

_Returns:_ `a%`=records checked, `b%`=items added.

[CAUTION]
====
`++ menu2` doesn't check these, so:

* `types$` must be long enough for every type: 4 characters for each, up to the highest `type`. A shorter one gives prefixes from whatever follows the string in memory.
* `titlelen` must be at most `size` − 14. A longer title runs on into the next menu item.
* A title shorter than the item's title field doesn't clear the rest of it, so the end of an earlier, longer title can show. Start from a freshly ``dim``ensioned array.
====

.i.GF: add up to 9 items for the subboards whose flags have bit 0 set
[source]
----
3513 &,16,1,42,q%(0,n),"1",ct$,80,s%(0,1),1,s%(2,1),s%(13,1),28,rn,9,1:n=b%
----

===== `&,16,2`: Draw Menu and Choose

`&,16,2,_size_,_menu%(0,first)_,_items_,_width_,_columns_,_rows_,_x_,_y_,_start_`

This prints the menu in a blue frame, from wherever the cursor is, and fills in each item's screen position and cursor links.
Items fill each column from top to bottom.
Then it waits for the user to choose, as `&,16,3` does.

`items`: the number of menu items.

`width`: the width of a column, in characters.
Each column takes `width` + 2 characters on the screen.

`columns`, `rows`: the size of the menu. For two columns, `rows` is `items`/2 rounded up (`n/2+.5`).

`x`, `y`: the screen column and row where the first item's hotkey is printed.
The menu is printed from the cursor's position, so these have to match it; they tell `&,16,3` where to put the cursor on each item.

`start`: the item the cursor starts on (0 for the first).

_Returns:_ `a%`=the item chosen, 0 for the first.

.i.IM: a two-column menu under a 4-line header
[source]
----
&,16,2,34,m%(.,1),n,17,2,n/2+.5,2,6,.:lm=a%+1:&,70,.,n/2+8.5:&"{white}":return
----

===== `&,16,3`: Choose from Menu

`&,16,3,_size_,_menu%(0,first)_,_items_,_start_`

This lets the user choose from a menu already on the screen:

* the cursor keys (or the ANSI sequences `ESC [ A` to `ESC [ D` from a remote terminal) move between items, wrapping around at the edges
* kbd:[Return] chooses the item the cursor is on
* a hotkey chooses its item at once. A two-key hotkey works only right after its prefix. If several single-key items share a hotkey, the last one is chosen.

_Returns:_ `a%`=the item chosen, 0 for the first.
