=== Function Keys [[im-function-keys]]

Sets the text of the eight programmable function keys, which kbd:[Ctrl] or kbd:[C=] with a function key types at the console (see <<function-keys>>).

==== Editing the Keys

Choose kbd:[G] (Function Keys) from the `IM` main menu.
The Function Key Editor lists F1 to F8, showing the first 35 characters of each.

. Type the number of a key, kbd:[1]-kbd:[8], to edit it.
Its text is shown for you to change; kbd:[Return] keeps it.
+
End the text with kbd:[_] (back arrow, kbd:[←]) to have the key press kbd:[Return] after it.
Only a kbd:[_] at the very end does this.
. Press any other key to finish.
. If you changed anything, `IM` asks:
** _Save Changes?_: kbd:[Y] saves the keys to `e.fkeys`, so they're there the next time the BBS starts.
** _Activate?_: kbd:[Y] puts them to use straight away.

A key can't be emptied from the editor: kbd:[Return] on an empty line leaves it as it was.

==== `e.fkeys`

The keys are kept in `e.fkeys`, a SEQ file on the Etcetera drive: eight lines, F1 to F8.
The BBS reads it when it starts (the "`Enabling Function Keys...`" step); without it, the keys are empty.

=== Modem Config [[im-modem]]

`i/IM.modem` sets up the modem: how Image BBS talks to it (the modem flags), the commands it sends to it (the init strings), and how it understands the modem's replies (the result codes).

====
NOTE: This section was written from the module's source (`core/i_IM.modem.lbl`).
The `nimodem.dat` options are new, and have not been tested on a running BBS yet.
====

The screen shows the modem's name and author, the 12 modem flags, the init strings, and this menu:

[%autowidth]
[%header]
|===
| Key | Action

| kbd:[1]-kbd:[9], kbd:[0] then a digit
| Change a modem flag (kbd:[0]: flags 10-12; see <<im-modem-flags>>)

| kbd:[A]
| Edit the custom init string, up to 35 characters (see <<im-modem-init>>)

| kbd:[B]
| Setup/Import Modem Config (see <<im-modem-setup>>)

| kbd:[C]
| Customize Current Result Code(s) (see <<im-modem-result-codes>>)

| kbd:[R]
| Re-select the port to configure (multi-port Lt. Kernal systems only)

| kbd:[X]
| Exit. If you changed a flag, you're asked "`Update Modem Flags?`"
|===

==== Modem Flags [[im-modem-flags]]

The flags are stored as a string of characters, `mt$`, one per flag.

[%autowidth]
[%header]
|===
| Flag | Setting | Values

| 1 | Maximum connection rate | `0` no modem, `1` 300, `2` 1200, `3` 2400, `4` 4800, `5` 9600, `6` 19.2k, `7` 38.4k bps
| 2 | Hang-up method | `D` DTR, `E` escape code
| 3 | Answer method | `A` auto-answer (`ATS0=1`), `M` manual answer (the BBS sends `ATA`)
| 4 | `ATH` after escape codes | `H` yes, `N` no
| 5 | Phone in local mode | `N` on the hook, `H` off the hook (callers get a busy signal)
| 6 | `ATH0` instead of `ATH` | `0` yes (`ATH0`), space: no (`ATH`)
| 7 | `ATH` in the init string | `H` yes, `N` no
| 8 | `ATX` value | `1`-`4`
| 9 | DTR | `N` normal, `R` reversed
| 10 | Standard | `0` CCITT (`ATB0`, international), `1` Bell (`ATB1`, US/Canada)
| 11 | RS-232 interface | `0` standard (user port), `1` SwiftLink cartridge (`$de00` only)
| 12 | Caller ID | `0` not available, `1` available (on both the modem and the phone line)
| 13-14 | (reserved) | `0`
|===

Flag 11 is also saved to record 32 of `e.data`, which is how the BBS knows which RS-232 driver to use.

==== Init Strings [[im-modem-init]]

Image BBS (`sub.modem`) resets the modem with `ATZ`, then sends it three strings.
The first two are made from the flags:

[%autowidth]
[%header]
|===
| String | Made from

| `e0v0` [`h`[`0`]] `x`_n_ `m`_n_ `b`_n_
| No command echo, numeric result codes; `h` if flag 7 is `H` (`h0` if flag 6 is `0`); `x` from flag 8; `m` the speaker setting (`m1` on, `m0` off), switched from the waiting-for-call screen; `b` from flag 10

| `s0=`_n_`s2=27s7=25`
| `s0=1` (auto-answer) if flag 3 is `A`, otherwise `s0=0`; escape character 27 (kbd:[Esc]); wait 25 seconds for a carrier

| _custom init string_
| Edited with kbd:[A]: anything else the modem needs, _e.g._ `m0&c1&d2` (speaker off, real DCD, DTR hang-up)
|===

`v0` makes the modem send numeric result codes, which are what the BBS reads: see <<im-modem-result-codes>>.

[TIP]
.Skipping the modem setup: hold kbd:[C=]
====
After each command, `sub.modem` waits for the modem to reply.
If no reply comes in time, it starts the whole setup again from `ATZ`, and keeps doing so: with no modem connected, or a modem (or `tcpser`) that isn't set up yet, the BBS never gets past this.

Hold down the kbd:[C=] (Commodore) key, on its own, to stop waiting: each command is sent, but its reply isn't waited for, so the setup finishes.
(`sub.modem` checks `peek(653)=2`: the shift-key flags at `$028d`, with only kbd:[C=] down.)

kbd:[C=] also aborts dialing out (`peek(653) and 2`), which shows "`Aborted`".
====

==== Result Codes [[im-modem-result-codes]]

With `v0` in its init string, a modem replies with a number followed by kbd:[Return], instead of words such as `CONNECT`.
Image BBS looks the number up in its result code table, `e.modem`, and acts on the entry's _flag_:

.Result Code Flags
[%autowidth]
[%header]
|===
| Flag | Meaning

| `0` | Error: the call failed
| `1` | Re-Loop: keep waiting, _e.g._ for `RING`
| `2` | Connect, 300 bps
| `3` | Connect, 1200 bps
| `4` | Connect, 2400 bps
| `5` | Connect, 4800 bps
| `6` | Connect, 9600 bps
| `7` | Connect, 19.2 kbps
| `8` | Connect, 38.4 kbps
|===

kbd:[C] (Customize Current Result Code(s)) asks for a result code number:

* kbd:[L] lists the table: number, flag, and text.
* A number already in the table edits its text (up to 26 characters) and flag; type `DEL` as the text to delete it.
* A new number adds it.

The table holds up to 50 result codes.

NOTE: The numbers are the modem's own: check its manual.
Most Hayes-compatible modems send `1` CONNECT, `2` RING, `3` NO CARRIER, `4` ERROR, `5` CONNECT 1200, `6` NO DIALTONE, `7` BUSY, `8` NO ANSWER and `10` CONNECT 2400; faster speeds vary from one modem to another.
Don't confuse a result code number with a flag: result code `2` is RING, while flag `2` means "`connect at 300 bps`".

| (none)

| `m0&c1&d2`

===== File Format

`nimodem.dat` is a sequential (SEQ) file, with each item on a line of its own.
Each profile is:

. the modem's name (up to 25 characters)
. the author (up to 20 characters)
. the 14 flag characters (see <<im-modem-flags>>)
. the custom init string, or `^` for none
. the number of result codes
. then, for each result code: its number, its flag (`0`-`8`) and its text (up to 26 characters), each on a line of its own

A line containing just `^` ends the file.

==== Using tcpser With VICE [[im-modem-tcpser]]

In VICE, `tcpser` can stand in for a Hayes modem: callers telnet to `tcpser`, which "`rings`" the BBS.

NOTE: The Image BBS 3.0 RS-232 routines handle up to 19200 bps, so run `tcpser` and VICE's RS-232 device at 19200.

. Start `tcpser` before VICE, _e.g._ `tcpser -s 19200 -v 127.0.0.1:25238 -p 6400`: 19200 bps, VICE connects on port 25238, and callers on port 6400.
. Start VICE with a SwiftLink connected to it: `x64sc -acia1 -acia1mode 1 -acia1irq 1 -myaciadev 2 -rsdev3 127.0.0.1:25238 -rsdev3ip232 -rsdev3baud 19200`.
`-rsdev3ip232` makes VICE and `tcpser` pass the modem's DCD and DTR lines, so the BBS sees calls arrive and can hang up.
. In `IM`, choose kbd:[J] (Modem Config), kbd:[B], then kbd:[4] and kbd:[3] to add the standard profiles, then kbd:[2] to import "`tcpser (VICE)`".

`tcpser` sends result code `14` (CONNECT 19200) when it answers at 19200 bps with its default `ATX4`, or `1` (CONNECT) with `ATX0`.
To see the commands the BBS sends and `tcpser`'s replies, start `tcpser` with `-t sS` (trace the serial data in both directions).

=== Set Time [[im-set-time]]

Sets the BBS's clock.
The BBS can read the date and time from a clock (a CMD device's real-time clock, a DS12C887 chip, an Ultimate, ...), or you can type them; `IM` remembers which, as the _clock source_.

.Set Time Menu
[%autowidth]
[%header]
|===
| Key | Option

| kbd:[A] | _Set Clock Using_ the clock source, for example "`Set Clock Using CMD Device 10`": sets the BBS clock from it now.
If the source is Manual Entry, it asks you for the date and time.
| kbd:[B] | _Set Clock Manually_: asks you for the date and time (only shown when the clock source isn't Manual Entry already).
| kbd:[C] | _Choose Different Clock Source_ (below)
| kbd:[M] | _Main Menu_
|===

When the clock has been set, the new date and time show for two seconds before the menu comes back.

==== Setting the Clock by Hand

You're asked for the year (00-99), month, date, hour (1-12), minute and A or P, each with the current setting shown: press kbd:[Return] to keep it.
The weekday is worked out from the date.
Then `IM` shows the new date and time and asks _Set the clock to ...?_: kbd:[N] starts again.

If a question isn't answered in 5 minutes, it gives up and leaves the clock as it was.

If the clock source is a CMD device or a DS12C887, you're then asked _Also set the ... clock?_: kbd:[Y] sets that clock to the new time too, so it's right the next time the BBS starts.

==== Choosing a Clock Source

[%autowidth]
[%header]
|===
| Source | Asks for | Notes

| Manual Entry | | You type the date and time.
| CMD Device's Clock | Device (8-30) | A CMD HD, FD or RAMLink with a real-time clock.
| Lt. Kernal's Clock | Port (1-2) |
| DS12C887 Clock Chip | Base Address (hex) | For example `D500`. In VICE: `x64sc -ds12c887rtc -ds12c887rtcbase 0xd500`.
| Ultimate's Clock | | A 1541 Ultimate or Ultimate 64, with its Command Interface turned on.
| TeensyROM (Time Only) | | The time from the TeensyROM; the date is the last one the BBS saved.
| Last AutoMaint Date | | The date and time of the last AutoMaint run.
|===

The choice is saved in `e.data` (record 37), and _Set Clock Using_ then uses it.

==== Setting the Clock Automatically [[im-set-clock-automatically]]

Unless the clock source is Manual Entry, the BBS also uses it by itself:

* *When it starts:* during "`Reading System Info`", the boot screen shows "`Setting Clock...`", then "`Clock Set.`".
If the clock doesn't answer, the BBS starts anyway, and the clock on the status line flashes until it's set.
With the Last AutoMaint Date as the source, the clock starts from the date and time of the last AutoMaint run.
* *Every few hours:* when the lightbar's `Trc` right check (_Time: Reset Clock_) is set, which alarm trigger `At1` does, the idle screen reads the clock source again, to correct the drift of the C64's clock.
It does this without a word, and does nothing for the Last AutoMaint Date, which would set the clock back.

==== From the Idle Screen

Option kbd:[1], Set Time, on the idle screen does the same as kbd:[A]: it sets the clock from the clock source, or asks for the date and time if that's Manual Entry.
If nobody answers within 5 minutes, the idle screen comes back with the clock unchanged.

==== Access-Aware Menus [[im-menus]]

When a caller types kbd:[?], the BBS shows the menu for where they are: menu 1 at the main prompt, menu 7 in General Files, and so on.
After a subsystem's menu, it shows menu 1 too, unless the caller aborts.

A menu can come from either of two files:

`s.menu` _n_ (SEQ, System drive)::
Plain text, shown as it is, to everyone.
Its MCI commands work as in any text file.

`e.menu` _n_ (PRG, Etcetera drive)::
The same lines, each with its own access number.
A caller sees only the lines their access group may see, so they don't read about commands they can't use.

If `e.menu` _n_ is there, the BBS uses it, and ignores `s.menu` _n_.

.Menus Shown by kbd:[?]
[%autowidth]
[%header]
|===
| Menu | Where

| 1 | Main prompt
| 2 | Message bases (`SB`)
| 5 | Up/download libraries (`UD`)
| 6 | E-mail (`EM`)
| 7 | General Files (`GF`) and News (`NF`)
| 9 | Exchange libraries (`UX`)
|===

Some `s.menu` files are always read as text, so an `e.menu` file for them would never be used: 3 (the text editor's help), 4 (local-mode commands), 8 (end-of-message commands), 10 (Which day), 12 (log-in commands) and `t1` to `t4`.

===== Converting a Menu

kbd:[C] (Convert Menu) loads `i/SM.conmenu`, which makes `e.menu` _n_ (Etcetera drive) from `s.menu` _n_ (System drive).

. At "`Menu #:`", type the menu's number.
Only numbered menus can be converted: `s.menu t1` to `t4` can't.
. Each line shows as it's converted.
Each line of `s.menu` _n_ becomes one item, up to 60 lines and 50 characters to a line; a line that is only kbd:[↑] ends the menu early.
. Every item starts with access `1023` (every group) and flags `1`, so the converted menu looks the same to everyone until you edit it.
The rest of the 60 items are left empty (access and flags `0`).
. `e.menu` _n_ is saved, and the drive's status shows (error 0 if all went well).
. "`Menu #:`" asks for another menu; kbd:[Return] goes back to the Editor Programs menu.

If there's no `s.menu` _n_, the drive's error shows (62, file not found), and "`Menu #:`" asks again.

WARNING: Converting replaces `e.menu` _n_ without asking, and every line's access goes back to `1023`.
To change a menu's text after setting the access numbers, change the text in the menu editor instead of in `s.menu` _n_.

To go back to the plain text menu, scratch `e.menu` _n_.

===== Editing a Menu [[im-menu-editor]]

kbd:[D] (Edit Menus) loads `i/SM.menuedit`.
At "`Edit Which Menu:`", type the number of a menu you've converted (kbd:[Return] goes back to the Editor Programs menu).
The editor lists all 60 items, one to a line:

----
 0: 1023 ...the first 30 characters of the line...
 1: 1023 ...
----

The first number is the item number (0 to 59), the second its access number.
Empty items are listed too, with access `0` and no text.
Then it asks:

----
Options: List Edit Quit

>
----

[%autowidth]
[%header]
|===
| Key | Option

| kbd:[L] | List the items again
| kbd:[E] | Edit an item: "`Edit #`" asks for its number (up to 2 digits).
kbd:[Return] edits item 0; a number over 59 goes back to "`Options:`".
| kbd:[Q] | Quit: if you changed anything, "`Changes made-- Save?`" asks whether to save (kbd:[Y]; anything else doesn't), then "`Edit Which Menu:`" asks for another
|===

Other keys do nothing.

WARNING: Convert a menu before editing it.
Between menus, the editor only clears the items' flags: if there's no `e.menu` _n_, the list shows the menu you edited last, and saving would make `e.menu` _n_ a copy of it.

Editing an item shows its settings:

----
Item#12:

1. Access: 1023
2. Flags: 1
3. Text:
...the line...

>
----

Type kbd:[1], kbd:[2] or kbd:[3] to change one; the item's settings show again afterwards.
Any other key goes back to "`Options:`".

[%autowidth]
[%header]
|===
| Setting | What it is

| Access
| Which access groups see the line, added up as for a General Files item: 1 for group 0, 2 for group 1, 4 for group 2, and so on to 512 for group 9.
`1023` shows the line to everyone, `512` to group 9 only, and `0` to nobody.
Up to 5 characters (see below for pseudo-local mode).

| Flags
| Not used: Convert sets it to `1` for a line and `0` for an empty item, and changing it makes no difference.
Up to 3 digits.

| Text
| The line itself, up to 50 characters, with its colors and MCI commands.
"`Text:`" shows the line as it is, for you to edit with the cursor keys.
|===

WARNING: Each prompt sets the setting to what you type, even if that's nothing.
kbd:[Return] at "`Access:`" or "`Flags:`" sets it to `0` (so at "`Access:`" it hides the line), and kbd:[Return] at "`Text:`" without changing anything blanks the line.
If you change one by mistake, quit without saving.

====== Lines for Pseudo-Local Mode

A line is also shown in pseudo-local mode (`zz`) when its access number has bit 15 (32768) set.
Only bits 0-9 (the groups) and bit 15 matter, so the easiest way to set bit 15 is to subtract 1024 from the access number:

[%autowidth]
[%header]
|===
| Type | Shows the line to | Listed as

| `-1024` | nobody, except in pseudo-local mode | `31744`
| `-1` | everyone, and in pseudo-local mode | `32767`
| `-512` | group 9, and in pseudo-local mode | `32256`
|===

The list and the item screen leave out bit 15, so these show as the numbers in the last column.
The editor takes at most 5 characters, and a number from 32768 up stops it with `?ILLEGAL QUANTITY ERROR`.

====== Example: Hiding Lines from the General Files Menu

The General Files menu (menu 7) ends with its sysop commands:

----
           Sysop Commands
  A  Add Items      Ex Edit Item #x
  Kx Kill Item #x
----

To hide those lines from callers, or to remove the Add and Edit line altogether:

. In `IM`, choose kbd:[N] (Base Editors), then kbd:[G] (Editor Utils).
. If `e.menu 7` isn't there yet, choose kbd:[C] (Convert Menu) and type kbd:[7], then kbd:[Return].
. Choose kbd:[D] (Edit Menus) and type kbd:[7].
. Find the line in the list, type kbd:[E] and its item number, then kbd:[1] (Access), and type the new number: `0` hides it from everyone, `512` shows it to group 9 only.
Do the same for each line to hide, including the "`Sysop Commands`" heading and its underlines.
. Type kbd:[Q] and kbd:[Y] to save.

==== The `MENU` Command

kbd:[MENU] at the main prompt runs `i.menuedit`, an older version of the same editor.
It only edits items 0 to 49, and it saves just those, so items 50 to 59 are lost.
Use kbd:[D] (Edit Menus) instead.
