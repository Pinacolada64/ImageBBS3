== Data Files [[data-files]]

These are the files Image keeps on its disks besides its programs (`im`, the ML, and the `i.`, `i/` and `sub.` modules).
A file's prefix says which of Image's drives it's on (see <<im-system-drives>> in the Configuration Editor):

[%autowidth]
[%header]
|===
| Prefix | Drive | Holds

| `s.` | 1, System | screens, help menus
| `f.`, `nm.log` | 2, E-Mail | mail waiting at login, the network log
| `e.`, `today.`, `nm.times` | 3, Etcetera | tables, settings, logs
| `d.` | 4, Directory | General Files libraries
| `u.` | 6, User | the user records
|===

`bd.data` is on the boot disk: it says where the Etcetera drive is (where `e.data` is), and holds the main prompt's text.

The release's `MASTER D2` disk has the screens and tables Image comes with; Image creates the rest as it runs (marked _created_ below).

This appendix says what each file is for.
How some of them are laid out inside (`e.data`, `e.menu` _n_, `s.m.protos`, `nm.P.count` and the `today.` files) is in the _Image BBS 3.0 Programmer's Reference Guide_, appendix "File Formats".

=== Screens: `s.` files [[data-files-screens]]

Most screens come in versions for each kind of terminal, and for 80 columns: Image adds the caller's terminal mode to the name (`0` ASCII, `1` Commodore colour and graphics, `2` ANSI), then `80` for an 80-column caller.
`s.welcome 1 80` is the welcome screen for a Commodore caller in 80 columns.
In the tables, _n_ stands for the mode, and `[80]` for the optional `80`.
A screen that isn't on the disk is skipped.

.Screens on the way in and out
[%autowidth]
[%header]
|===
| File | Shown | By

| `s.login` _n_ `[80]` | before the Login Options menu | `i.lo` (3116)
| `s.detect` _n_ `[80]` | after the terminal is detected, if "Use s.detect Files" is on (`i.LB`, option G) | `i.lo` (3562)
| `s.lines/screen` | asks how many lines the caller's screen has, when that isn't set | `i/lo.on` (4030)
| `s.welcome` _n_ `[80]` | after logging in, before the login modules | `i/lo.on` (4184)
| `s.start 0`, `1`, `2` | never: `i/lo.on` (4183) asks C/G callers for `s.start` and the weekday's digit (`s.start4`), not these names |
| `s.mail` | at login, when mail is waiting | `i/lo.mail`
| `s.new user` | a new user's application, first | `i/lo.new` (4014)
| `s.nu welcome` | the welcome letter `i.VF` sends a user it validates | `i.VF` (3154)
| `s.end` _n_ `[80]` | at logoff, after "Bye" | `i.lo` (3202)
| `s.logon help` | Help at the Login Options menu | `i/lo!help`
| `s.tchkmail` | mailed to an account after a failed login on it | `i/lo!telecheck`
| `s.errmail` | mailed to a caller whose call caused an error | `im`
|===

WARNING: In `i/lo.on`, a missing `s.welcome` screen also skips every login module: line 4192 tests `e%`, which the `e.loginmods` load (4190) doesn't set, so it still holds "file not found" from the screen.
Keep the `s.welcome` screens on the System disk, or add `gosub 5` to the end of line 4190 (as `i/lo.instant` does after its own load).

=== Today in History: `today.` _Mon_ and `s.today/hist` [[data-files-today]]

Each night, AutoMaint's `i/lo/today` (from Maint Mods) reads this month's `today.` file from the Etcetera drive, picks out today's facts, and writes them to `s.today/hist` on the System drive.
The login module `i/lo-today` shows `s.today/hist` to callers.
Copy the twelve `today.` files to your Etcetera disk to use them.

Each `today.` file is a month of facts: people born, things that happened, and holidays or reminders, each under its date.
You can add your own; the layout of the lines is in the _Programmer's Reference Guide_, appendix "File Formats".
