== What`'s New in 3.1 [[changes-3-1]]

Image BBS 3.1 is the 3.0 release of 2023-12-31, with the fixes and features below.
Sections of the guides that describe something new or changed in 3.1 are marked _New in 3.1_ or _Changed in 3.1_.

=== For the Sysop

==== Clock

* The clock is set automatically when the BBS starts, from the clock source chosen in setup or in `IM`: a CMD device, Lt. Kernal, DS12C887, Ultimate, TeensyROM, or the last AutoMaint date.
3.0 only read CMD and Lt. Kernal clocks at boot.
* The lightbar's `Trc` right check (Time: Reset Clock) re-reads the clock source every few hours, whichever it is (3.0: CMD only).
* `IM` K (Set Time) is a menu: set the clock from the clock source, set it by hand, or choose a different clock source.
Setting it by hand can also set a CMD or DS12C887 clock, so it's right at the next boot.
* Setting the clock by hand gives up after 5 minutes without an answer, so the idle screen comes back (3.0 waited for ever).
* The idle screen's 1) Set Time uses the clock source.

==== Idle Screen and Login

* `i/lo.idle2` is gone: the lightbar's `Alt` right check (flag 55) now makes `i/lo.idle` show New Messages in place of Calls/Log.
* `sub.modem` is loaded once at start-up, not twice.
* `i/lo.login`: L) Toggle Linefeeds on the Login Options Menu, which shows two options to a line.
* Two sentences that broke over two lines are mended: "`...set to that time?`" (`i/lo.on`) and "`Enter NEW if you have no Login ID...`" (`i/lo.login`).
* Auto-Maint with no modules in `e.maintmods` no longer stops with `?undef'd statement error` (`i.lo`).

==== `IM` Configuration

* `IM` D is called Module Editors (3.0: Logon Editor): its menu edits Login Mods, AutoMaint Mods (3.0: Maint Mods), Wall Ads and the Quicklist.
* The last item of `IM`'s sub-menus is called Main Menu (3.0: Quit), as it goes back to `IM`'s main menu; the main menu's Q is still Quit.
* `IM` J (Modem Config): modem profiles in `nimodem.dat` can be imported, created and edited, with a 19.2k tcpser profile for VICE.
* `IM` C (Payroll Editor): Edit with an entry number out of range no longer stops with `?undef'd statement error`.
* `i.UU`: the user account editor has a cursor menu.

==== Other Changes

* A user's time-per-day limit can be two digits.
* Answering No to "`Would You Like To Leave Feedback?`" is quicker (blocks free is only checked for Yes).
* The sysop window's Area field clears a longer module name properly.
* At boot, the "`Insert All System Disks`" menu's Reset C64 asks "`Are You Sure?`" first, and the blocks free list lines up its numbers.
* A system error only turns the border red if the lightbar's `Trb` right check is set.
* At boot, `im` shows the date it was last changed ("`im Revision: Oct 14, 2026 12:08 PM`"), from its own date string; the release always showed "`Apr. 17, 2023 6:55 AM`".

==== Converting From 1.2

* Without `d.data` on the Program Disk, "`Convert from Image 1.2`" makes it from the 1.2 system's `bd.data`: it asks where that is and where the new System Disk is, sets the Program Disk to the boot disk, and lists the six drives to check (`i/su.config`; see <<convert-12-run>>).
1.2's WF editor isn't needed.
* It converts `e.macros` too: 1.2's macros move down one record, the count from `e.i.macro` goes in record 1, and `e.i.macro` is scratched.

==== Fixes

* kbd:[Ctrl]/kbd:[C=] with a function key could lock up the BBS; programmable function keys work, up to 75 characters.
* After a password prompt (`&,1,x,1`), everything printed was masked until the next input.
* Without `nm.origin` (NetMail's origin line), posts were read without their text while NetMail Enable was on, and NetSub posts got a junk origin line (`i/MM.sb-post`; see <<netmail-problems>>).
* Turning on pseudo-local mode (`ZZ`) wrote a broken date to `e.zz log`; it's the date and time now (`sub.local`).
* At the console, `ZZ` says "`Local Mode: On`" or "`Off`", as it does for a remote sysop (`sub.local`).
* Mail for a user whose handle is 14 characters or longer could go astray: the mail files (`m.` _handle_, and `f.` _handle_, shown at login) are named with only the start of the handle, and some modules kept 13 characters of it while `i/lo.on` looked for 14.
Every module now keeps 14 (`im`, `i.EM`, `i/EM.extra`, `i.FM`, `i/lo-fmail`, `i.ED`, `i.VF`, `i.UU`, `i/NM.mail`, `i/NM.update`, `i/NM.sort`, `i/SM.fixer`, `sub.local`).
Upgrading from 3.0 needs those users' mail files renamed (see <<changes-3-1-upgrading>>).

==== Upgrading From 3.0 [[changes-3-1-upgrading]]

Mail files are now named with 14 characters of the handle, not 13 (see <<changes-3-1>>, Fixes).
On a 3.0 system, a user whose handle is 14 characters or longer has mail files named with only 13, which 3.1 won't find.
`i.rename mail` renames them all: run it once, as the sysop, before the BBS takes calls, with kbd:[R] at the main prompt (class 3, the module drive; see <<modules.adoc#_command_classes,Running Modules>>).
For each handle of 14 characters or more, it renames `m.` and `f.` files on the E-Mail drive (Image drive 2) from 13 characters of the handle to 14, and lists what it did.
It leaves two kinds alone, and lists them:

* A file named with 13 characters that another handle starts with too: it held both users' mail, so sort it out by hand.
* A file whose new name is already there.

To rename a file by hand, use a DOS command on the E-Mail drive.
For example, for the handle `THE GREAT GATSBY`,

----
r0:m.THE GREAT GATS=m.THE GREAT GAT
----

renames that user's mail file (send it to the E-Mail drive's device; on a CMD device, put the partition number in place of the `0`).
Either way, rename them before the BBS takes calls under 3.1, so that no mail is saved under a new name while the old file is still there.
Handles of 13 characters or fewer aren't affected.


* `&,5` returns the version (3.1) in `lp` and the revision in `a%` (3.0: 2.0, and `a%` not set).
* `&,9` shows number variables as digits (3.0 showed garbage).
* `&,1` clears its password flags when input ends.
* `++ copier` has `&,16,3`, which compares two files.
* `sub.clocks`: reads (and for CMD and DS12C887, writes) every supported clock; `im=0`-`11`.
* `++ visual`: Image 2.0's unfinished visual editor, converted.
* `im`:
** Line 28 copies `a$` into `cm$` (`cm$=a$+""`); modules set `pr$`, `cm$` and `p$` as copies, not pointers into the program.
** The boot code sets the clock with `sub.clocks`; its own CMD and Lt. Kernal clock code is gone.
** `im`'s revision date is in line 3074 (`core/im.lbl`, line 627): `d1$="4"+"2610149208"`, an 11-digit Image date (weekday 1-7, then `yymmdd`, the hour with 80 added for PM, and the minutes).
Change it when you change `im`: `&,15` turns it into the date shown at boot.
It's also `d1$`'s and `am$`'s value until the clock is set and `e.data` is read.
** Line 15 (after displaying a file) resets the output defaults (line 12).
** Line 32 (`m.` mail file) keeps 14 characters of the handle (the release kept 13).
** Line 43 (`e.say`) closes the file if it can't be read.
** `cm$` has no "`L:`" prefix while a module loads; the status line shows L instead.
** Line 370 (show a mode On/Off) no longer changes `an$`.
** "`Are You Sure?`" (lines 93 and 95) is one subroutine, line 98.
** The jump table has 23 new entries: 504, 506-508, 510, 513, 515, 525, 541, 543, 545-548, 556, 558-564.
