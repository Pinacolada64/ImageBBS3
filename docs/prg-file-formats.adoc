== File Formats

=== Introduction

This appendix shows how some of Image's data files are laid out inside.
For every data file, which drive it's on and what reads or writes it, see the _Image BBS 3.0 Sysop Manual_, appendix "Data Files".

====
.Option Lists
To show when options are mutually exclusive (there can be only one option chosen from a group), the following notation is used:

[ _option 1_ | _option 2_ | _option 3_ ]

means that of the three options presented, option 1 _or_ option 2 _or_ option 3 is saved in that position in the file.

==== `e.menu` _n_ [[e-menu]]

An access-aware command menu: when it's there, `sub.menus` shows it instead of the text file `s.menu` _n_, one line at a time, only the lines the user's access group may see.
`i/SM.conmenu` makes it from `s.menu` _n_, and `i/SM.menuedit` edits it (see the Sysop Guide's "`Access-Aware Menus`").

It's a PRG file on the Etcetera drive (`dr=3`): a struct of 60 records of 60 bytes (3600 bytes), loaded into `jm%(29,59)` with <<prg-structures.adoc#load-struct,`&,60,2` Load Struct from Disk>> and saved with <<prg-structures.adoc#save-struct,`&,60,3` Save a Struct to Disk>>.
Record _r_ is menu line _r_ (0-59).
Integers are high byte first, as in any integer array.

[%autowidth]
[%header]
[cols="1m,1m,4"]
|===
| Bytes | Field | Purpose

| 0-1
| jm%(0,r)
| Flags.
Not used: `i/SM.conmenu` sets it to `1` for a line and `0` for an empty record, and nothing reads it apart from the editors, which show it and let you change it.
Other structs keep a flags word here for <<prg-structures.adoc#scan-struct,`&,60,6` Scan Struct>> to set; `sub.menus` tests the access field directly instead.

| 2-3
| jm%(1,r)
| Access: bit _n_ (0-9) for access group _n_, so `1023` is every group and `0` nobody.
Bit 15 (`32768`) shows the line in pseudo-local mode (`zz`) too.
`sub.menus` picks the lines with <<prg-structures.adoc#scan-numbers,`&,60,8` Scan Numbers>>: `&,60,8,60,60,2^ac%+zz*32768,jm%(1,.),fd%(1),.`, which keeps a record when this field ``and``ed with the bits isn't `0`.

| 4-5
| jm%(2,r)
| Not used: `i/SM.conmenu` sets it to `-1` for a line, and nothing reads it.

| 6-9
| jm%(3-4,r)
| Not used (`0`).

| 10-59
| jm%(5-29,r)
| The line's text, up to 50 characters (<<prg-structures.adoc#put-string,`&,60,0` Put String>>, <<prg-structures.adoc#get-string,`&,60,1` Get String>>), with its colors and MCI commands.
`sub.menus` prints it with `&` after `q$`.
|===

==== `today.` _Mon_ [[today-mon]]

`today.Jan` ... `today.Dec`, on the Etcetera drive, are Today in History's facts, a file a month: AutoMaint's `i/lo/today` reads this month's, and writes today's facts to `s.today/hist`, which the login module `i/lo-today` shows.

Each is a sequential file of lines, each ended by a carriage return:

.today. File Format
[%autowidth]
[%header]
|===
| Columns | Holds

| 1 | `B` born today, `S` happened today, `R` don't forget (a holiday or a reminder)
| 2-5 | `MMDD`: the date. `i/lo/today` compares only the day (columns 4-5).
| 6-9 | The year, right-aligned: a space before a three-digit year such as `742`; spaces for `R`
| 10 | [ space \| `C` \| `1`-`7` ]: a space starts a fact; `C` is more of the fact above; `1` (Sunday) to `7` (Saturday) starts a fact shown only on that weekday, compared with the first character of `d1$`
| 11- | The text
|===

* A fact longer than one line goes on in `C` lines, each with its first line's type and date.
* A holiday on a weekday that moves is a line for each date it can fall on, each with that weekday: Thanksgiving, the fourth Thursday in November, is `R1122` to `R1128`, each with `5`.
A weekday fact must fit on one line: its `C` lines have no weekday, so on the other weekdays they'd show on their own.
* A line can be at most 80 characters: `i/lo/today` reads them with <<prg-ampersand-calls.adoc#_2_disk_file_input,`&,2` Disk File Input>>, which reads no more.
* `i/lo/today` keeps at most 20 lines of one type for a day (`dim zt$(3,20)`), `C` lines included; a 21st stops it with `?bad subscript`.
* A line starting with `*` is a header (`*MMDDYYYY Birthdays`), and `^` ends the file.
`i/lo/today` skips a `*` line only because its columns 4-5 never match a day.
